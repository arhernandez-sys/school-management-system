> - **Four behaviours that are subtle and deliberately differ from sibling modules** — each commented at its site: (1) `class_subjects.is_active` is **NOT** filtered in the picker or `/grades/me`, because past-year offerings are inactive and the year switcher must still list them (the Assessments picker *does* filter it); (2) the semester resolves against the **section's** academic year — using the globally-active semester would hand a principal browsing an archived year an empty gradebook; (3) grading bands come from the **section's year's** scale, not the active year's, so an archived year keeps the scale in force then (§10.4) and a later scale edit can't reletter history; (4) Grades has its **own** `ClassSubjectRef` keyed `id` with `teachers[].full_name` — Attendance's uses `name`. The three refs are not interchangeable.
> - **Gradebook rows are a UNION** of the active roster and any student holding a grade row (the latter `is_active_member=false`, `enrollment_id=null`, sorted after active members). Dropping a student must not make their marks vanish from the teacher's view.
> - **`PUT .../grades` is all-or-nothing**: every entry is validated and every offender collected before anything mutates, so one bad row in a batch of forty leaves the gradebook untouched (asserted). Codes: 422 `duplicate_entry` / `student_not_enrolled` / `score_exceeds_max` / `score_status_conflict` / `makeup_not_allowed`, 409 `year_archived`, 404 unknown. `makeup_not_allowed` resolves `allow_makeup` through the **full §10.2a chain**, not just the school row.
> - **`letter` is `letter?: string` on the wire, never `null`** — a `_LetterOptional` wrap-serializer drops the key when unset, matching the frontend's conditional spread. A plain optional field would emit `"letter": null`, which is off-contract.
> - **RELEASE FIX (latent bug, `assessments/service.py::set_release`).** Release/unrelease now accept an optional `{student_ids?}` body (api-spec §7); `payload: ReleaseRequest | None = None` keeps every existing caller and test working. **A whole-column release now also resets every grade row's `is_released` to NULL.** Without that reset, a row left at `False` by an earlier per-student unrelease keeps overriding the column (the read path is `grade.is_released ?? assessment.is_released`) and stays invisible to the student even after the teacher releases the whole assessment. Regression-tested.
> - **Divergence from the mock:** a non-owning teacher gets **404 everywhere**, including the write path where MSW returns 403. Consistent with `assert_teacher_owns_class_subject` and the no-existence-leak rule; the frontend only renders `apiErrorMessage(err)`, so there is no behavioural difference. >   - **Teachers** post only to sections they are assigned to; they see those sections' notices plus `all` and `teachers`.

>   - **Admins do NOT see teacher-authored announcements.** A teacher's class notice is between them and their class. Since a teacher can only ever create a `class` announcement, "not teacher-authored" is the whole of that rule.
>   - An author always sees their own, whatever the audience — and may open their own **expired or still-scheduled** notice (the one relaxation vs the feed) so they can edit it.
>   - **The principal's old "read anything by id" exemption is REMOVED**, otherwise the by-id route would have been a backdoor around the rule above. `_assert_can_modify` was tightened to match: author, or either admin acting on an **admin-authored** notice.

> **🐛 TWO REAL BUGS FOUND AND FIXED while testing this module** (both pre-existing, neither specific to Announcements):
> 1. **`app/core/errors.py::validation_error_handler` erased the name of any field literally called `body`.** It filtered `("body","query","path")` out of the whole `loc` tuple, but only `loc[0]` is a location prefix — so a validation error on a field *named* `body` produced `loc = ("body","body")`, collapsed to empty, and reported as `_root`. `AnnouncementFormDialog` maps `fields.body` to its textarea, so the message would never have reached the field. Fixed to strip only the leading prefix, and to skip list indices so `entries.0.student_id` still reports as `student_id`. **This handler is shared by every module**, hence the full-suite re-run.
> 2. **Whitespace-only titles/bodies passed validation and were saved empty.** `Field(min_length=1)` accepts `"   "` (three characters) and the service's later `.strip()` silently stored `""`. Fixed with `StringConstraints(strip_whitespace=True, min_length=1)` so stripping happens *before* length validation. The same latent bug existed in Events and was fixed there too. Regression tests use whitespace, not `""` — an empty string was already caught, which is why this survived.
